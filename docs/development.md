# Development and security

Follow the [coding conventions](coding-conventions.md) for the application structure, UI component boundaries, and review expectations.

Server imports use native `#views/*`, `#presentation/*`, and related responsibility aliases from `package.json`. The npm source commands enable the `development` condition; ad hoc source execution needs `node --conditions=development --import tsx <file.ts>`. Production aliases resolve to `dist/` under the default conditions after `npm run build`; start with `npm start`.

Node 26 is the selected LTS; dependencies are pinned in the lockfile. Set `DATABASE_URL` to a local `file:` SQLite path or an authenticated Turso `libsql://` origin, and `PORT` to an integer from 1 to 65535; local defaults are `file:.data/collection.db` and `3000`. Turso requires `DATABASE_AUTH_TOKEN`: use a read-only token for the runtime and a separate write token for migrations. Database URL queries are rejected. `SITE_URL` is an HTTP(S) origin used for canonical links and sitemap; it defaults locally to `http://localhost:<PORT>`. Vercel requires a remote database and explicit `SITE_URL`. See [production deployment](deployment.md) for settings and release ordering.

`npm run dev` and ordinary Instagram commands load `.env` if present, with existing environment variables taking precedence. Ordinary `db:migrate` uses the environment passed to it and does not load `.env`; set `DATABASE_URL` explicitly if targeting another database. `db:migrate:turso` and `import:instagram:turso` require the separate ignored `.env.turso-import` file; see [manual Turso imports](instagram-access.md#manual-instagram-imports-into-turso) for first-time and repeat use. Run commands from the repository root. `db:migrate` tracks ordered SQL files and checksums in `schema_migrations` and is repeatable; never edit an applied migration. Local databases live in ignored `.data/`. The runtime requires an existing database and R2 read-only credentials, keeps local reads on one SQLite `query_only` connection, and has no write routes. Import commands can target local SQLite or Turso; R2 restore remains local-only.

`npm test` exercises real route responses with an in-memory SQLite database and Testing Library. `npm run typecheck`, `npm run lint`, `npm run test:coverage`, `npm run build`, `npm run test:production` (after build), and `npm run test:e2e` run the individual checks. The browser suite starts and stops its own test-only server on port 3107, with an in-memory database, synthetic fixtures and a fake image service; it uses Playwright's matching headless Chromium shell. Install it with `npx playwright install chromium --only-shell` if needed. `npm run verify` combines the final checks after review.

GitHub's **Verify** workflow runs this gate only for PRs targeting `main`. The independent **Production Migration** workflow runs on pushes to `main` or a manual run on `main`. It checks pending migrations and backs up the database before applying them; Vercel requires its **Migrate production database** check for production promotion. See [deployment](deployment.md) for environment secrets, backup artifacts, and setup.

HTML responses use `public, max-age=0, s-maxage=300, stale-while-revalidate=60`; errors and signed redirects use `no-store`. The maintained JS and CSS use stable URLs with `public, no-cache, must-revalidate`, so browsers revalidate them on use. Content-hashed assets (currently the favicons and pinned htmx) retain one-year immutable caching; change their URL whenever bytes change. CSP denies everything by default and permits same-origin styles and images from the configured R2 endpoint; templates escape data and image links are limited to content-hashed media paths. Never put credentials or untrusted raw HTML in public data. Local header tests do not prove CDN behavior, invalidation, or production image delivery. Those remain deployment work. See [Instagram importing](instagram-access.md) for the separate write workflow.

Archive tag links use `/archive?tag=<normalized-tag>` and select one tag at a time. The archive lists tags by matching post count, then alphabetically in Finnish; the introductory About post is excluded from those counts. Tags present on every archive post are omitted from the filter list but remain available on post pages. The selection is retained in pagination, fragments, post return links, and browser history; clearing it returns to the full archive. Archive documents use `/archive?page=N` for one twelve-post batch. `/archive?page=N&through=M` represents the inclusive accumulated range, limited to twenty batches; invalid ranges return 400. On downward scrolling, the enhanced archive automatically loads the next batch; the “Näytä lisää” control remains available for manual use. The enhancement appends `/archive/fragments?page=M&start=N` without putting that fragment URL in browser history. Progress is announced to assistive technology without a visible page counter; loading errors and retry controls remain visible. Automatic loading pauses on failure until the visitor retries. After twenty batches, navigation continues to the next ordinary page. Archive card links preserve the validated range for return navigation; scroll positions are stored per archive URL in session storage when available. Without JavaScript, the next control remains a normal page link.

The archive uses the pinned, self-hosted htmx asset in `public/assets/` and its accompanying license in `licenses/`. Its external bootstrap disables evaluation, fragment scripts, injected indicator styles, and htmx history, and limits requests to the same origin. The bootstrap source is `assets/archive.js`; update htmx with a new content-hashed filename and layout reference.

The About page at `/about` presents the introduction identified by its Instagram media ID. That record is excluded from home and archive listings and its former post URL redirects to About; the source record remains available to the importer. The page shows an unavailable message if the record is missing.

Post galleries start as an ordered list of image links and enhance to a carousel and native dialog when JavaScript is available. Navigation arrows, image count and expand action overlay the artwork; pagination dots sit below it. The thumbnail strip is visible when a gallery has multiple images. Keyboard navigation, swipe and full-image links remain available. The gallery uses a small TypeScript controller; no Alpine runtime is needed for its local state. `npm run assets:build` compiles `src/client/gallery.ts` to the ignored `public/assets/gallery.js`.

The theme follows the device preference until a visitor selects light or dark; the switcher toggles between light and dark and remembers the choice. The mobile navigation uses a native disclosure and works without JavaScript. `npm run assets:build` compiles `src/client/theme.ts` to the ignored `public/assets/theme.js`. The same command copies `assets/{style,sitemap}.css` and `assets/{archive,images}.js` to their stable served URLs. It runs automatically before `npm run dev`, `npm run build`, and `npm run test:e2e`. Edit the source files, never the ignored copies. A source change requires a new build or dev-server restart; `npm start` uses the output of `npm run build`.

When replacing a content-hashed vendor asset or icon, review whether old cached pages or open tabs may still request its previous URL before deleting the old file from `public/assets/`. Removing a file from the repository does not remove it from prior deployments or invalidate CDN caches.
